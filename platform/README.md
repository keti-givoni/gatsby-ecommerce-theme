# פלטפורמת המנויים: הפודקאסט עם לבוש מותאם

אפליקציית Next.js שמארחת את גרסאות הפרקים עם הלבוש המותאם מאחורי מנוי חודשי, משולמת דרך Grow (משולם), עם Supabase לכניסה ולמסד הנתונים. תוסף הכרום בתיקייה `../extension` פונה לאפליקציה הזו.

## מה יש כאן

| נתיב | תפקיד |
|---|---|
| `/` | דף נחיתה |
| `/login` | כניסה בקישור למייל (בלי סיסמה) |
| `/episodes` | רשימת הפרקים (פתוח לכולם) |
| `/watch/[slug]?style=` | צפייה בגרסה. מנויים רואים את הנגן, אחרים רואים הצעת מנוי |
| `/subscribe` | טופס הצטרפות שמעביר לדף התשלום של Grow |
| `/subscribe/success` | חזרה מהתשלום, ממתין לאישור המנוי |
| `/account` | מצב המנוי, ביטול, בחירת סגנון צפייה |
| `/admin` | הוספת פרקים וגרסאות (רק לכתובות ב-`ADMIN_EMAILS`) |
| `GET /api/episodes/by-youtube/[id]` | ה-API שתוסף הכרום משתמש בו |
| `POST /api/grow/create` | יוצר תהליך תשלום ב-Grow |
| `POST /api/grow/notify` | ה-webhook ש-Grow קורא לו אחרי כל חיוב |
| `POST /api/grow/cancel` | ביטול הוראת הקבע |

## הקמה

### 1. Supabase

1. פותחים פרויקט (או מחדשים את הפרויקט הקיים `thekey`).
2. מריצים את `supabase/migrations/0001_init.sql` ב-SQL Editor. זה יוצר את הטבלאות, ההרשאות (RLS) והפונקציה `is_active_subscriber`.
3. ב-Authentication ← URL Configuration מוסיפים את `https://<הדומיין שלך>/auth/callback` ל-Redirect URLs.
4. מ-Project Settings ← API לוקחים את `URL`, `anon key` ו-`service_role key`.

### 2. Grow

1. בממשק Grow יוצרים **דף תשלום מסוג הוראת קבע** (חיוב חודשי חוזר). לוקחים את קוד הדף (`pageCode`).
2. לוקחים את מזהה המשתמש (`userId`) ואת מפתח ה-API.
3. לבדיקות משתמשים בסביבת ה-sandbox (`GROW_ENV=sandbox`), ולייצור עוברים ל-`production`.
4. ה-webhook (`notifyUrl`) נשלח אוטומטית בכל יצירת תשלום, אין צורך להגדיר אותו בממשק.

### 3. משתני סביבה

מעתיקים את `.env.example` ל-`.env.local` (או למשתני הסביבה ב-Vercel) וממלאים.

### 4. הרצה מקומית

```
npm install
npm run dev
```

### 5. פריסה ל-Vercel

מייבאים את הרפו, מגדירים Root Directory = `platform`, מזינים את משתני הסביבה ומפרסמים. אחרי הפריסה מעדכנים את `NEXT_PUBLIC_SITE_URL` לדומיין הסופי, כי הוא משמש לכתובות החזרה ול-webhook של Grow.

## זרימת התשלום

1. משתמש מחובר ממלא שם וטלפון ב-`/subscribe`.
2. השרת יוצר שורת מנוי במצב `pending`, קורא ל-`createPaymentProcess` של Grow עם `paymentNum` (מספר החיובים החודשיים) ומפנה לדף התשלום.
3. אחרי תשלום, Grow קורא ל-`/api/grow/notify`. השרת מאמת שה-`processToken` תואם למה שנשמר (או שמזהה הוראת הקבע מוכר), מעדכן את המנוי ל-`active` עם תאריך סיום תקופה של חודש קדימה, וקורא ל-`approveTransaction`.
4. בחידושים חודשיים Grow קורא שוב ל-notify, והתקופה מוארכת בחודש. חיוב שנכשל מעביר ל-`past_due` עם 3 ימי חסד.
5. ביטול: `/api/grow/cancel` קורא ל-`updateRecurringPayment` ומסמן `canceled`. הצפייה נשארת פתוחה עד סוף התקופה ששולמה.

כל קריאה נרשמת בטבלה `payment_events`, כולל קריאות שנדחו, כדי שאפשר יהיה לבדוק תקלות.

## מה חייבים לאמת מול Grow לפני עלייה לאוויר

התיעוד של Grow לא היה נגיש במלואו בזמן הכתיבה, אז שלושה פרטים מבוססים על דוגמאות חלקיות ומסומנים בקוד:

1. **ערך `statusCode` לחיוב מוצלח.** ברירת המחדל היא `2`. אפשר לשנות ב-`GROW_SUCCESS_STATUS_CODES` בלי לגעת בקוד.
2. **שם השדה של מזהה הוראת הקבע** בקריאת ה-webhook. הקוד מקבל `recurringDebitId`, `directDebitId` או `recurringId`. אם Grow שולחים שם אחר, מוסיפים אותו ב-`parseCallback` בקובץ `lib/grow.ts`.
3. **פרמטרים של `updateRecurringPayment`** (ביטול). אם הקריאה נכשלת, המנוי מסומן כמבוטל אצלנו והאירוע `cancel_needs_manual` נרשם, כדי לבטל ידנית בממשק Grow.

הדרך הבטוחה: לעשות תשלום אחד ב-sandbox, לפתוח את `payment_events` ולראות בדיוק אילו שדות הגיעו.

## איפה מאחסנים את הווידאו

בשדה `video_url` של כל גרסה שמים קישור. הנגן תומך ב:

- Vimeo (מומלץ: מאפשר להגביל הטמעה לדומיין שלך)
- Bunny Stream או Mux (קישור iframe)
- YouTube לא רשום (unlisted). פחות מומלץ, כי מי שמקבל את הקישור יכול לשתף אותו.
- קובץ MP4 או HLS ישיר

הקישורים עצמם נשלפים רק למנויים פעילים (גם ברמת מסד הנתונים דרך RLS).
